# Create Auction Workflow - Deep Analysis

Reference doc for E2E testing. Updated as bugs are found/fixed.

## Overview

The create-auction flow lets a user sell their prediction signal as an encrypted auction. It spans: frontend form, EIP-712 signature, Next.js proxy, daemon API, and on-chain FHE marketplace.

## End-to-End Flow

```text
User on /create
  |
  | Step 1: Fill auction form
  |   Select prediction market event (from ExamplePredictionMarket contract)
  |   Choose position: YES or NO signal
  |   Enter secret reasoning (plaintext textarea)
  |   Select duration (5m to 48h)
  |
  | Step 2: EIP-712 signature
  |   Domain: { name: "InsiderStreams", version: "1", chainId: 11155111 }
  |   Types: CreateAuction [eventId, privateLeg, duration, timestamp]
  |   signTypedData via wallet (mock wallet auto-signs in tests)
  |
  | Step 3: POST /api/create-auction (Next.js proxy)
  |   Body: { eventId, eventTitle, endTime, prediction, secretPayload,
  |           secretDataCid, secretDataKey, timestamp, signature }
  |   Proxied to daemon POST /create-auction
  |
  v
Daemon (synchronous — waits for FHE tx)
  |
  | Step 4: Verify signature, create/get user
  |   verifySignedRequest() -> recover signer address
  |   getOrCreateUser(address) -> { userId, address }
  |
  | Step 5: Create auction on-chain
  |   marketplace.createAuction(userId, eventId, eventTitle, endTime,
  |     prediction, secretDataCid, secretDataKey)
  |     -> FHE encryption: encryptBatch(
  |          { type: "ebool", value: prediction },
  |          { type: "euint256", value: secretDataKey })  ~10s
  |     -> writeContract("createAuction", [...])  ~15-30s
  |     -> Parse AuctionCreated event for auctionId
  |
  | Step 6: Store secret data in SQLite
  |   insertSecret(auctionId, userId, secretDataCid,
  |     secretDataKey, secretPayload, eventData)
  |
  | Step 7: Respond to frontend
  |   { success: true, auctionId, txHash }
  |
  v
Frontend shows success card
  |
  | "Auction live" card with:
  |   - Auction ID
  |   - Transaction hash (etherscan link)
  |   - "View auction" link
```

### 3. Next.js API Proxy

**File:** `src/app/api/create-auction/route.ts`

Simple proxy: `proxyToDaemon("/create-auction", body)` -> returns daemon response directly.

### 4. Daemon: POST /create-auction

**File:** `apps/daemon/src/api.ts`

Required fields: `eventId`, `eventTitle`, `endTime`, `prediction`, `secretPayload`

Optional but generated by frontend: `secretDataCid`, `secretDataKey`

Flow:
1. `verifySignedRequest()` -> recover signer address
2. Validate required fields (400 MISSING_FIELDS if any missing)
3. `getOrCreateUser(userAddress)` -> get/create pseudonymous userId
4. Generate `secretDataCid` = SHA-256 hash of secretPayload
5. Generate `secretDataKey` = random 32-byte hex string (AES key)
6. Call `marketplace.createAuction(userId, eventId, eventTitle, endTime, prediction, secretDataCid, secretDataKey)`
7. Store secret in SQLite: `insertSecret(auctionId, userId, cid, key, payload, eventData)`
8. Respond: `{ success: true, auctionId, txHash }`

**Error codes:**
- `MISSING_FIELDS` (400): Missing required fields
- `FHE_TX_FAILED` (500): On-chain FHE tx failed

**IMPORTANT:** Unlike `/bid` and `/deposit`, the daemon WAITS for the on-chain tx to complete before responding. This is because the frontend needs the `auctionId` from the `AuctionCreated` event.

### 5. Daemon: marketplace.createAuction()

**File:** `apps/daemon/src/marketplace.ts`

```typescript
async function createAuction(
  sellerId: string,
  eventId: number,
  eventTitle: string,
  endTime: number,
  prediction: boolean,
  secretDataCid: string,
  secretDataKey: bigint,
): Promise<{ txHash: string; auctionId: number }>
```

Flow:
1. `encryptAuctionInputs(marketplace_addr, admin_addr, prediction, secretDataKey)` -> ~10s (single ZK proof for ebool + euint256)
2. `withAdminLock`: `writeContract("createAuction", [
     sellerId, eventId, eventTitle, endTime,
     handle_prediction, handle_key, inputProof
   ])`
3. `waitForTransactionReceipt`
4. Parse `AuctionCreated` event from receipt logs -> extract `auctionId`
5. Return `{ txHash, auctionId }`

### 6. Contract: createAuction()

**File:** `contracts-fhe/contracts/FHESecretMarketplace.sol`

```solidity
function createAuction(
    string calldata sellerId,
    uint256 eventId,
    string calldata eventTitle,
    uint256 endTime,
    externalEbool encryptedPrediction,
    externalEuint256 encryptedSecretDataKey,
    bytes calldata inputProof
) external onlyOwner returns (uint256 auctionId)
```

Validations:
- `endTime > block.timestamp` (AuctionEndTimeInPast)
- `eventId < nextEventId` (revert if event doesn't exist)

On-chain:
1. `FHE.fromExternal(encryptedPrediction, inputProof)` -> `ebool`
2. `FHE.fromExternal(encryptedSecretDataKey, inputProof)` -> `euint256`
3. `FHE.allowThis()` for both handles
4. Store auction struct with sellerId, eventId, endTime, encrypted fields
5. Emit `AuctionCreated(auctionId, sellerId, eventId, eventTitle, endTime)`

## Timing Summary

| Step | Duration | Notes |
| --- | --- | --- |
| Form fill + sign | <2s | Mock wallet auto-signs |
| Daemon receives | <1s | HTTP round-trip |
| FHE encryption (batch) | ~10s | ZK proof for ebool + euint256 |
| Admin lock wait | 0-60s | If other admin tx in flight |
| createAuction tx | ~15-30s | Sepolia block time |
| **Total** | **~25-90s** | User sees spinner during daemon wait |
| Subgraph indexing | +30-180s | For auction to appear in listings |

## E2E Test Considerations

### Frontend Test Flow

```typescript
// Navigate to create page
await page.goto("/create");

// Wait for events to load
await expect(page.getByText("Prediction market event", { exact: true }))
  .toBeVisible({ timeout: 15_000 });

// Select event
const eventCombobox = page.getByRole("combobox").first();
await eventCombobox.click();
await page.getByRole("option").first().click();

// Select position
await page.getByRole("button", { name: "YES" }).click();

// Enter secret signal
await page.locator("textarea").fill("My prediction reasoning...");

// Submit
await page.getByRole("button", { name: "Sell YES signal" }).click();

// Wait for success (daemon waits for on-chain tx)
await page.getByText("Auction live").waitFor({ timeout: 180_000 });
```

### Programmatic Test Flow (via daemon API)

```typescript
const result = await createTestAuction(sellerAccount, {

  privateLeg: "yes",

```

### Prerequisites

- At least one open prediction market event (not settled, endTime > 10min)
- Wallet connected (auto-connected via mock wallet in tests)
- No admin lock contention (daemon submits sequentially)

### Subgraph Indexing Delay

After `createAuction` succeeds, the auction won't appear in listings/search until the subgraph indexes the `AuctionCreated` event. This typically takes 30-180s on Sepolia.

For E2E tests that need to navigate to the auction page immediately after creation, use the `auctionId` from the daemon response and handle the 404/not-found case:

```typescript
// Retry if subgraph hasn't indexed yet
const notFound = page.getByText("This page could not be found");
const isNotFound = await notFound.isVisible({ timeout: 3_000 }).catch(() => false);
if (isNotFound) {
  await page.waitForTimeout(30_000);
  await page.goto(`/auction/${auctionId}`);
}
```
